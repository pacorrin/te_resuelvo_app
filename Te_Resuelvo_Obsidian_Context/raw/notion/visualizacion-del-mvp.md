# Visualizacion del mvp — MVP Web, Diseño Operativo y de Negocio

**Modelo: Pago por cliente (lead)**

## Puntos importantes
- Pago por cliente (lead)
- WhatsApp como canal operativo
- Sin registro de usuarios finales
- Control total de monetización
- Bajo riesgo técnico

## 1. Principios del MVP (no negociables)
1. Sin registro de clientes finales
2. Captura inmediata de leads
3. Proveedor paga antes de ver datos
4. WhatsApp como canal principal
5. Control manual al inicio
6. Escalabilidad posterior

## 2. Flujo del CLIENTE (lado demanda)
1. Cliente entra a la web
2. Selecciona el rubro
3. Completa formulario: nombre, zona/colonia, WhatsApp/teléfono, descripción del problema
4. CTA: "Recibe propuestas de proveedores verificados"
5. Confirmación: "Estamos buscando proveedores disponibles para tu solicitud"

El cliente no paga, no se registra, no espera nada complejo.

## 3. Flujo del PROVEEDOR (lado oferta)

### Alta de proveedor (manual)
Tú creas el usuario y le asignas: rubro, zona, tipo de trabajos, método de pago.

### Visualización de oportunidades
El proveedor ve: rubro, zona aproximada, tipo de problema, precio del lead.
NO ve: nombre, teléfono, dirección, WhatsApp.

### Desbloqueo del cliente (pago por lead)
1. Proveedor selecciona una oportunidad
2. Ve: "Desbloquea este cliente por $X"
3. Realiza pago
4. Sistema (o manualmente) libera: nombre, WhatsApp, detalle completo

## 4. Flujo OPERATIVO (detrás)
- Lead entra → se guarda en base simple → se notifica (WhatsApp/email interno)
- Proveedores reciben notificación: "Nuevo cliente disponible – AC – Colonia X"
- Pago: transferencia/link/efectivo al inicio, liberación manual del contacto
- El MVP NO necesita automatizar esto aún

## 5. MVP Web – Módulos necesarios
1. Landing + servicios (qué es, cómo funciona, rubros, CTA)
2. Formulario de cliente (simple, sin fricción)
3. Panel de proveedor básico (lista de oportunidades, estado bloqueado/disponible, botón "Desbloquear cliente")
4. Backoffice mínimo (crear proveedores, crear oportunidades, marcar como pagado, liberar contacto)

## 6. Monetización clara desde el día 1 — Precio por lead

| Rubro | Precio lead |
|---|---|
| Aire acondicionado | Alto |
| Electricidad | Medio |
| Plomería | Medio |
| Limpieza | Bajo |

Regla: Lead = oportunidad real, no spam.

## 7. Ventajas del modelo
No necesitas controlar el servicio, no dependes del cierre, cobras antes, el proveedor decide, no hay discusiones post-servicio. Perfecto para MVP.

## 8. Riesgos y mitigación
- **Proveedor se queja del lead** → definir "lead válido", reposición si no responde
- **Pocos proveedores** → pre-reclutar antes de lanzar, AC como rubro ancla

## 9. Resumen 30–45 días
- Semana 1: definir rubros iniciales, precio por lead, reclutar proveedores
- Semana 2: diseñar flujo web, formularios, WhatsApp operativo
- Semana 3: panel proveedor simple, backoffice mínimo
- Semana 4: piloto real, ajustes, primeros ingresos
